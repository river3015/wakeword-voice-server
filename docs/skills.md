# スキル（AIを通さない処理）

現在のスキル：[リスト](#リストskillslists)、[天気](#天気skillsweather)、[音楽](#音楽skillsmusic)。

文字起こしの後、AIへ渡す前に振り分け層を置く。決まった言い回しに一致した発話は、スキルがプログラム側で入力を検証して実行する。どのスキルにも一致しなければ従来どおりAIへ渡す。AIの権限は広げない。

```text
文字起こし → 制御語（会話終了など） → スキル（登録順に試す） → 一致なし → AI
```

## 仕組み

- `usecase.Skill`（`Name`と`Match`）を満たす型を`cmd/wakeword/app.go`の`newSkills`に登録する。Goの動的プラグイン（`.so`）は使わず、ビルド時に組み込む。
- `Match`は副作用を持たず、一致した場合だけ実行する処理を返す。処理は読み上げる返答（`Outcome.Reply`）と、必要なら読み上げの後に行う処理（`Outcome.AfterSpeech`）を返す。音楽の再生開始のように、返答の読み上げと音が重なる操作は後者で行う。判定は規則ベース（正規表現）で、AIによる分類はしない。質問の形の発話は一致させない。
- 返答はAIの返答と同じ経路で文ごとに合成・再生する。スキルの依頼と返答も会話履歴（メモリのみ）に残し、続けてAIへ「さっき何を追加した？」と聞けるようにする。
- スキルが失敗したら「依頼を処理できませんでした。」と読み上げ、エラーとして記録して待ち受けに戻る。
- スキルは設定の`[skills.*]`で有効にする。既定はすべて無効。
- macOSのアプリの操作は`internal/adapter/applescript`の共通処理でosascriptを実行する。値はスクリプトに埋め込まず`--`の後ろに引数で渡し、エラーはosascriptのエラー番号だけを記録する。
- スキルは任意で`usecase.SkillVocabulary`（`Vocabulary`）を実装できる。有効なスキルの語彙をまとめ、whisper-serverへ`prompt`（認識のヒント）として渡す。Whisper baseは短い語を誤りやすく、ヒントなしでは「メモ」が「目も」、「ToDo」が「どうぞ」、「買い物」が「カイモノ」になった。ヒントはAIへの質問の文字起こしにも同じく渡る。

## リスト（`[skills.lists]`）

macOSのリマインダー.appのリストへ追加し、未完了の項目を読み上げる。`shopping`・`todo`・`memo`に保存先のリスト名を書く。リストは事前にリマインダー.appで作成する。起動時にリストの有無を確認し、ない場合は起動しない。

| 種類 | 言い回しの例 |
| --- | --- |
| 追加 | 「買い物リストに牛乳を追加して」「牛乳を買い物リストに入れといて」「ToDoに歯医者の予約を登録して」 |
| メモ | 「明日は燃えるゴミの日とメモして」「明日は燃えるゴミの日、メモして」「メモ、駐車場は3階」 |
| 読み上げ | 「買い物リストを読み上げて」「やることリストに何がある？」 |

- 追加後に「買い物リストに『牛乳』を追加しました。」と、保存された項目名を読み返す。誤認識に気づけるようにするため。リスト名はヒントで正しく認識されても、項目は誤認識され得る（合成音声で「歯医者」が「会社」、「明日は燃えるゴミの日」が「あすはモエルゴミの人」になった）。
- 項目は60文字以内、制御文字を含まないものに限る。1回の発話で1項目として登録する（「牛乳と卵」は1項目になる）。
- 読み上げは未完了の項目を最大10件。それ以上は件数だけ伝える。
- 操作は`osascript`でAppleScriptを実行する。リスト名と項目はスクリプトに埋め込まず、`--`の後ろに引数として渡す。osascriptのエラー出力には項目名が含まれ得るため、エラー番号だけを記録する。
- 初回はmacOSが、起動元のアプリ（ターミナルなど）にリマインダーの操作の許可を求める。LaunchAgentから起動する場合の許可の扱いは未確認。
- リマインダーにiCloudを使っている場合、登録した項目はiCloudへ同期される。会話履歴や音声は保存しない。

### リストの検証記録（2026-10-04）

- 単体テスト：言い回しの判定（質問を一致させないことを含む）、追加後の読み返し、読み上げ件数の上限、偽のosascriptでの引数の渡し方・エラー番号のみの記録・タイムアウト、振り分け層（一致時にAIを呼ばない、不一致時はAIへ渡す、失敗時の読み上げ）。
- 実機（macOS 26.5.2、リマインダー.app）：リスト一覧の取得は約0.7秒、未完了項目7件の取得は約1.9秒。存在しないリストを指定すると起動時エラーになることを確認。
- 実機の一往復：macOSの`say`（Kyoko）で作った3件の依頼WAVを`--request-wav`で順に流した。語彙ヒントの導入前は、文字起こしが「カイモノリスト…」「…目もして」となり、3件ともAIへ渡った（AIは読み取り専用で、書き込みは起きていない）。導入後は3件ともスキルが処理し、買い物に「牛乳」、メモに「あすはモエルゴミの人」が登録されたことをリマインダーで確認した。確認後にテスト項目は削除した。
- 応答時間（録音完了から）：追加は最初の再生まで約3.2〜3.7秒、うちosascriptでの追加が約2〜2.5秒。読み上げ依頼は約1.9秒。AIへ渡した場合は4.1〜6.0秒だった。
- 未確認：人の声での一往復、マイクで待ち受けた状態での利用、ToDoへの実機登録。

## 天気（`[skills.weather]`）

設定した1地点の、今日と明日の予報を読み上げる。地点を発話で指定することはできず、「大阪の天気は？」のような依頼はAIへ渡す。

| 言い回しの例 | 返答の例 |
| --- | --- |
| 「今日の天気は？」「天気を教えて」「今日は傘いる？」「あすは、かさいる?」 | 今日はくもり。最高気温23度、最低気温16度です。降水確率は4パーセントです。今の気温は19度です。 |
| 「明日の天気予報を教えて」「明日傘必要かな」 | 明日はくもり。最高気温24度、最低気温17度です。降水確率は17パーセントです。 |

- 予報は[Open-Meteo](https://open-meteo.com/)の予報API（`/v1/forecast`）から取得する。APIキーは不要。利用条件と出典表示は[OSSの利用条件と費用](licensing-and-costs.md)に記載した。
- 送るのは緯度・経度だけで、小数2桁（約1km）に丸めて送る。音声や文字起こしは送らない。日の区切りは地点の時間帯（`timezone=auto`）。
- 天気はWMOの天気コードを日本語にして読み上げる。降水確率が欠けている日は降水確率に触れない。
- 気象庁のJSONは、公式の利用規約（公共データ利用規約）の対象だが、APIとしての仕様書がなく予告なく変わり得るため採用しなかった。

### 天気の検証記録（2026-10-04）

- 単体テスト：言い回しの判定（地点の指定や仕組みの質問は一致させない）、読み上げ文（マイナスの気温、降水確率の欠落）、偽のAPIサーバーでの座標の丸めと応答の読み取り、空の応答や不正なJSONのエラー。
- 実際のAPI：公開地点（東京駅付近）で今日と明日の予報を取得し、上の返答例の文になることを確認した。
- 未確認：利用者の地点を設定しての音声からの一往復。

## 音楽（`[skills.music]`）

ミュージック.appを操作する。ライブラリにある曲とプレイリストだけを扱う。Apple Musicのカタログを検索して再生する操作は対象外（AppleScriptでできるかは未確認）。

| 操作 | 言い回しの例 | 動き |
| --- | --- | --- |
| 再生 | 「音楽をかけて」「再生して」 | 「音楽を再生します。」と読み上げてから再生する。止まっていて再生中の曲がなければ、ライブラリ全体を再生する |
| プレイリスト | 「作業用のプレイリストをかけて」「プレイリスト、ドライブを再生して」 | 名前が完全に一致するプレイリストを、読み上げの後に再生する。なければその旨を伝える |
| 停止 | 「音楽を止めて」「一時停止」「ストップ」 | 先に一時停止してから返答する |
| 曲送り | 「次の曲」「曲をスキップして」「前の曲に戻して」 | 読み上げの後に操作する |
| 再生中の曲 | 「今かかってる曲は何？」 | 曲名とアーティストを読み上げる |

- 起動時にミュージック.appを操作できるかを確認する。初回はmacOSが自動化の許可を求める。
- 音楽の再生中も、待ち受け・録音・返答の読み上げは音楽を止めずに行う。音楽が鳴っている中でウェイクワードと依頼を聞き取れるかは未確認。必要なら、呼びかけを検出したら音量を下げるなどの対策を、実機で確認してから加える。

### 音楽の検証記録（2026-10-04）

- 単体テスト：言い回しの判定（音楽についての質問は一致させない）、再生は読み上げの後・停止は読み上げの前に行うこと、プレイリストがない場合の返答、偽のosascriptでの引数の渡し方・許可エラー。
- 実機（ミュージック.app）：状態の取得、存在しないプレイリストの確認、再生、再生中の曲名とアーティストの取得、次の曲、一時停止がそれぞれ0.2〜0.4秒で成功した。再生状態の変化は確認したが、耳では確かめていない。
- WAVでの一往復：`say`で作った「音楽をかけて」「今かかってる曲は何？」「音楽を止めて」を順に流し、3件とも音楽のスキルが処理して、最後は一時停止の状態になった。最初の声まで1.2〜2.1秒。
- Whisperの書き起こし：天気・音楽の言い回しはほぼそのまま認識された。「明日は傘いる？」は「あすは、かさいる?」になったため、規則を広げた。
- 未確認：音楽の再生中に人の声でウェイクワードと依頼を聞き取れるか。
