# 応答時間

発話の終わり（録音完了）から最初の声が出るまでを応答時間とする。`bin/wakeword once`と`serve`は、一往復ごとに`timings_ms`を出力する。

| 項目 | 意味 |
| --- | --- |
| `transcribe` | 文字起こしの完了まで |
| `first_chunk` | AIの返答が届くまで |
| `first_audio` | 最初の文の再生開始まで。体感の待ち時間 |
| `total` | 最後の再生終了まで |

## 測定（2026-10-03、Apple Silicon）

同じ8.6秒の連結WAV（Hey Mycroft＋日本語の依頼）を使い、VOICEVOXは起動済みの状態で測った。返答はいずれも22〜24文字の1文。Codexの所要時間は回ごとに数秒ばらつく。

| 段階 | Python版 | Go版（Codex既定） | Go版（reasoning_effort=low、3回） |
| --- | --- | --- | --- |
| 文字起こし | 0.95秒（whisper-cli、CPU、毎回モデル読込） | 0.17秒 | 0.17秒 |
| Codex | 8.2秒 | 8.6秒 | 6.9〜8.4秒 |
| 合成〜再生開始 | 2.2秒（全文） | 0.6秒 | 0.6秒 |
| 応答時間 | 約11.3秒 | 9.4秒 | 7.5〜9.0秒 |

Python版の値は状態表示の時刻から求めた。Go版はプログラム内の計測値。Python版の合成2.2秒には、エンジン起動後の最初の合成で話者モデルを読み込む時間が含まれているとみられる（推測）。Go版は起動時に話者を初期化するため、エンジンを自分で起動した直後の一往復でも0.6秒だった。

## 分かったこと

- Codex以外の待ち時間は、約3.2秒から約0.8秒に減った。文字起こしは、whisper-serverの常駐とMetalの利用で約0.8秒短縮。合成は、文ごとの合成と起動時の話者初期化で約1.6秒短縮。
- 残りの大半はCodex。`codex exec --json`で調べると、CLIの起動は約70msで、15トークンの返答に約5.3秒かかった。入力は約1万6千トークンで、エージェント用の指示が含まれる。`reasoning_effort=low`の効果は小さい。
- 長い返答では、文ごとの並行処理によって、全文の合成を待たずに最初の文から再生できる。2文目以降も、前の文の再生中に合成が進む。
- これ以上速くするには、APIを直接ストリーミングで呼ぶ経路が必要になる。モデルの振り分けを導入する際に検討する。Codexを使う限り、約5秒の固定的な待ちは残る。

## 調整できる設定

- `reasoning_effort`：Codexの推論の深さ。既定は`low`。
- `capture.silence_seconds`：発話終了の判定に使う無音時間（既定1.2秒）。短くすると速くなるが、話の途中で切れやすくなる。
- `gpu`：whisper-serverでMetalを使う（既定true）。
