# 応答時間

発話の終わり（録音完了）から最初の声が出るまでを応答時間とする。`bin/wakeword once`と`serve`は、一往復ごとに`timings_ms`を出力する。

| 項目 | 意味 |
| --- | --- |
| `transcribe` | 文字起こしの完了まで |
| `first_chunk` | AIの返答が届くまで |
| `first_audio` | 最初の文の再生開始まで。体感の待ち時間 |
| `total` | 最後の再生終了まで |

## 測定（2026-10-03、Apple Silicon）

同じ8.6秒の連結WAV（Hey Mycroft＋日本語の依頼）を使い、VOICEVOXは起動済みの状態で測った。返答はいずれも22〜24文字の1文。Codexの所要時間は回ごとに数秒ばらつく。

| 段階 | Python版 | Go版（Codex既定） | Go版（reasoning_effort=low、3回） |
| --- | --- | --- | --- |
| 文字起こし | 0.95秒（whisper-cli、CPU、毎回モデル読込） | 0.17秒 | 0.17秒 |
| Codex | 8.2秒 | 8.6秒 | 6.9〜8.4秒 |
| 合成〜再生開始 | 2.2秒（全文） | 0.6秒 | 0.6秒 |
| 応答時間 | 約11.3秒 | 9.4秒 | 7.5〜9.0秒 |

Python版の値は状態表示の時刻から求めた。Go版はプログラム内の計測値。Python版の合成2.2秒には、エンジン起動後の最初の合成で話者モデルを読み込む時間が含まれているとみられる（推測）。Go版は起動時に話者を初期化するため、エンジンを自分で起動した直後の一往復でも0.6秒だった。

## Claude（2026-10-04）

`provider = "claude"`、`reasoning_effort = "low"`、既定モデルで測った。Claude CLIは返答を逐次出すので、最初の文ができた時点で合成を始められる。

| 項目 | 値 |
| --- | --- |
| CLIの起動（initイベントまで） | 1.2〜1.6秒。ユーザー設定を読まない指定にしても1.2〜1.3秒で、ほぼ変わらない |
| 最初の返答断片（連結WAV、35文字の返答） | 3.5秒 |
| 応答時間（同上） | 4.1秒 |
| 最初の返答断片（長い返答の2回） | 4.1〜4.7秒 |
| 応答時間（同上） | 7.4〜8.2秒。最初の文が長いと、その文が完成するまで待つ |

返答の終了後、CLIは要約などの後処理で約1秒動き続ける。Go版はこれを待たずにCLIを止める。

## スワップを減らした後（2026-10-04 夜）

搭載メモリ8GBのMacで、Claudeデスクトップアプリの仮想マシン（約2.4GB）などを止め、スワップ使用量を約8.8GBから約5.2GBに減らしてから測った。依頼は`say -v Kyoko`で作った16kHzのWAV（呼びかけなし）。設定は上と同じ`provider = "claude"`。

| 依頼 | 経路 | 返答の文字数 | first_chunk | first_audio |
| --- | --- | --- | --- | --- |
| 富士山の高さ（2回） | AI | 21 | 2.9〜3.6秒 | 4.3〜4.9秒 |
| おすすめの朝ごはん | AI | 107 | 2.3秒 | 4.4秒 |
| 今日の天気（2回） | 天気スキル | 55 | 1.3秒 | 2.0〜2.2秒 |

文字起こしは0.15〜0.20秒。最初の返答から再生開始までは0.7〜2.1秒で、最初の文が長いほど長い。スワップが多かった時の測定（AIは3.9〜6.0秒、スキルは1.1〜3.7秒）と比べると、ばらつきの上限が下がった。ただし回数が少なく、メモリの影響とCLIやネットワークのばらつきを分けられていない。

## 分かったこと

- Codex以外の待ち時間は、約3.2秒から約0.8秒に減った。文字起こしは、whisper-serverの常駐とMetalの利用で約0.8秒短縮。合成は、文ごとの合成と起動時の話者初期化で約1.6秒短縮。
- 残りの大半はCodex。`codex exec --json`で調べると、CLIの起動は約70msで、15トークンの返答に約5.3秒かかった。入力は約1万6千トークンで、エージェント用の指示が含まれる。`reasoning_effort=low`の効果は小さい。
- 長い返答では、文ごとの並行処理によって、全文の合成を待たずに最初の文から再生できる。2文目以降も、前の文の再生中に合成が進む。
- Codexを使う限り、約5秒の固定的な待ちは残る。Claude CLIは逐次の返答を使えるので、短い返答なら応答時間は約4秒になった。
- さらに速くするには、APIを直接ストリーミングで呼ぶ経路（CLIの起動約1.3秒が不要になる）が候補。モデルの振り分けを導入する際に検討する。

## 調整できる設定

- `provider`：`claude`はCLIの逐次受信が使えるので、現状では`codex`より速い。
- `reasoning_effort`：推論の深さ。既定は`low`。
- `model`：空ならCLIの既定。より小さいモデルで速くなるかは未測定。
- `capture.silence_seconds`：発話終了の判定に使う無音時間（既定1.2秒）。短くすると速くなるが、話の途中で切れやすくなる。
- `gpu`：whisper-serverでMetalを使う（既定true）。
