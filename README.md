# Wakeword Voice Server

macOS上でマイク入力を待ち受け、ウェイクワードでClaudeやCodexとの音声会話を始めるためのプロジェクトです。

## 作りたい理由

スマートフォンでAIに音声入力するたびにボタンを押す手間を減らしたい。Macから少し離れた場所にいても、呼びかけるだけで依頼し、返答を聞けるようにすることを目指します。

## 想定する利用環境

- macOSを搭載したMacを電源につなぎ、常時稼働させる。
- 起動スクリプトの`caffeinate`で画面とシステムのスリープを抑止する。蓋を閉じた状態での運用は対象外。
- Macに接続したマイクとスピーカーを使う。内蔵機器で離れた場所から使えるかは実機で確認する。
- 初期段階ではMacで直接音声を受け付ける。スマートフォン用アプリやネットワーク越しの音声入力は初期範囲に含めない。

## 目指す使い方

1. 音声サーバーを起動し、ウェイクワードを待ち受ける。
2. 普段の会話では使いにくい専用のウェイクワードで呼びかける。
3. 受付開始を音などで知らせ、続く依頼を録音する。
4. 発話終了を検出し、音声をテキストに変換する。
5. 選択したClaudeまたはCodexに依頼を渡す。
6. 返答を音声で読み上げる。
7. 会話を続けるか、ウェイクワードの待ち受けに戻る。

自宅での非商用利用を前提に、英語のウェイクワードで起動し、依頼と返答は日本語にします。現在のPoCは「Hey Mycroft」を使い、追加の依頼でも呼びかけます。会話履歴は一定時間メモリに保持します。人の声での検証後に呼びかけや受付方法を調整します。

## 想定する構成

```text
マイク → ウェイクワード検出 → 発話区間の検出 → 音声認識
                                                  ↓
                                        Claude / Codexへの依頼
                                                  ↓
スピーカー ← 音声合成・読み上げ ← 応答の取得
```

Claudeへの`claude -p`、Codexへの`codex exec`によるCLI連携を候補とします。APIなど別の方法も検討対象です。呼び出し方、認証、会話履歴の継続方法、利用条件は公式仕様と実機で確認してから決めます。

## 初期の開発範囲

まずは「呼びかけ → 依頼 → 音声で返答 → 待ち受け復帰」の一往復を動かします。

- macOSでのマイク入力とウェイクワード検出
- 発話終了の検出、無音時のタイムアウト、音声認識
- ClaudeまたはCodexとの連携。最初に対応する連携先は実装前に決める
- 応答の音声読み上げ
- 待機中・録音中・処理中・読み上げ中の状態確認
- 起動・停止操作と、認識や連携に失敗した場合の待ち受け復帰
- 読み上げ音をマイクが拾って再起動する問題への対策

一往復が安定した後に、会話履歴を維持した追加の依頼や、常駐起動の運用を整えます。

## 実装前に決めること

なるべくOSSを使い、音声処理はローカル実行を優先します。コードだけでなくモデルと生成音声の利用条件も確認します。候補のライセンス・利用条件・費用は[調査メモ](docs/licensing-and-costs.md)にまとめています。認識精度と応答速度は動作検証の段階で評価します。

- 実装言語と常駐プロセスの起動・停止方法
- ウェイクワードと検出エンジン、日本語・距離・周囲の雑音への対応
- 音声認識と音声合成の方式（ローカル／外部サービス）
- 最初に対応するAIと連携方式、必要な認証
- AIに渡す作業ディレクトリと実行権限、承認が必要な操作の扱い
- 会話履歴の保持期間、会話終了・キャンセル方法
- 処理中や読み上げ中の追加発話・割り込みの扱い
- 許容する応答時間と、離れた場所で使えるかを判断する実機確認の条件

## 音声データと実行権限の方針

待ち受け中の音声はローカルで扱い、外部の音声認識を使う場合はウェイクワード検出後の依頼音声に送信範囲を限定する方針です。文字起こしした依頼は、選択したAIの連携方式に応じて送信します。

通常運転では音声・文字起こしを恒久保存せず、会話履歴は上限と有効期限を設けてメモリに保持します。明示的な検証用ファイル保存は別途指定します。認証情報や秘密値をコード、ログ、読み上げに含めないようにします。音声で起動したことだけを理由に、AIの実行権限を広げたり、承認を省略したりしません。
